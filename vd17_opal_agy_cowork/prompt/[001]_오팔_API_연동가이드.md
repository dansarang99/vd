## 1. 개요 및 설계 철학
Google Opal은 Google Labs에서 공개한 차세대 노코드 AI 워크플로우 빌더로, 자연어 프롬프트를 통해 데이터 수집, 모델 추론, 도구(Tool) 호출, 데이터 정제를 노드(Node) 형태로 시각화하고 즉시 배포할 수 있는 플랫폼입니다.

본 파이프라인에서는:
1. **공공데이터포털(data.go.kr)**의 "전라북도 완주군 로컬푸드 품목별 판매현황" REST API를 소스로 사용합니다.
2. API 키가 없거나 공공 서버 장애 상황에서도 파이프라인이 멈추지 않도록 **시간대별(09시~20시) 동적 매출 증분 시뮬레이터(Dynamic Real-Time Fallback Engine)**를 내장합니다.
3. Google Opal의 워크플로우 규격에 맞는 **`opal_app_blueprint.json`**을 자동 생성하여, 사용자가 Opal(opal.google)에 원클릭 임포트하거나 Antigravity Cowork 엔진에서 직접 실행할 수 있도록 지원합니다.

## 2. 데이터 스키마 (완주군 로컬푸드 표준)
* `saleDate` / `saleYm`: 판매일자 (YYYY-MM-DD 또는 YYYYMM)
* `saleHour`: 판매시간 (09시 ~ 20시)
* `storeNm`: 매장명 (해전점, 둔산점, 혁신점, 모악산점, 삼례점, 용진점 등 6개 직매장)
* `itemCategory`: 농산물 카테고리 (과채류, 엽채류, 과수류, 곡류, 가공식품, 버섯류)
* `itemNm`: 품목명 (완주 생강, 구이 친환경 딸기, 이서 배, 삼례 토마토, 봉동 당근, 모악산 표고버섯 등)
* `saleUnit`: 판매단위 (kg, 상자, 팩, 단, 세트)
* `unitPrice`: 단위당 평균 판매가 (원)
* `saleQty`: 누적 판매수량
* `saleAmt`: 누적 판매금액 (원)

---

## 3. Google Opal 워크플로우 노드 구성
1. **Input Trigger Node**: 시간 주기(1시간) 또는 수동 트리거
2. **API Collector Step**: REST API GET 요청 (ServiceKey, params)
3. **Data Transformer Step**: XML/JSON 파싱 및 표준화된 CSV 스트림 변환
4. **Agent Analysis Step (Gemini)**: 이상치 탐지 및 핵심 지표 요약
5. **Output Sink Node**: `result/latest_sales.csv` 파일 덤프 및 다운스트림 EDA 엔진 트리거
